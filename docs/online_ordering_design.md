## 架构

- **前端**：复用 `web/ourea-scan`，不新建项目。
  - 地址：`?t=<桌码>` 仍然是桌边点餐；新增 `?s=<店铺短名>` 进入线上下单，`?o=<订单令牌>` 是订单状态页。以后可以给线上入口配单独的域名。
  - 先把 `App.jsx`（1055 行）里通用的部分拆成共享组件：菜品卡、菜品详情、弹层、小海狸、搜索和分类、过敏筛选。桌边点餐继续用这些组件，行为不变。
  - 线上下单是另一个外壳：店铺头图、营业状态、自取时间、本机购物车（不是整桌共享）、结账（名字、电话、邮箱）、先付款后下单、订单状态。
  - 页面样子（2026-11-17 老板要求）：Arke 是自己的店铺页，不沿用桌边点餐的外观，没有小海狸。手机：一栏，顶部分类标签，底部结账条，弹层。电脑（宽度 ≥1024）：左边搜索和分类，中间门店卡片和菜品网格，右边购物车常开，结账是左右两栏的对话框。
  - 不搬过来的：进门页、整桌共享购物车、呼叫服务员、按轮次的订单、"点够不点多"里按桌的部分。
  - 这样也把 Scan 改进清单第 7 条（外带 / 自取二维码）一起做了。
- **数据**：按 `docs/database_design.md` 新建 `online` schema，只能通过 `public.online_*` RPC 读写。
  - `online.stores`：短名、营业时间、自取准备时间、是否开放线上、最低起送额。
  - `online.delivery_zones`：按距离或邮编划区，每区配送费和起送额。
  - `online.orders`：订单，明细放在 `items`（JSONB，和桌边扫码单同一格式）。取货方式 `PICKUP` / `OWN_DELIVERY` / `THIRD_PARTY`；状态：待付款 → 已付款待接单 → 已接单（含预计时间）→ 备好 → 已取 / 配送中 → 完成；另有已取消、已退款。
  - `online.payments`：这个业务线自己的付款表（按"每条业务线自己的交易表"规则，不往别的业务线表里抄）。
  - 顾客第一期不注册账号：填名字、电话、邮箱；状态页链接发到邮箱。
- **店里接单**：
  - 有 Ourea / Iris 的店：新订单横幅 + 提示音，接单时选准备时间，自动打厨房单或拣货单。
  - 没有终端的店：Cael 里一个网页接单台（平板浏览器开着就行）。
- **零售特有**：拣货单；缺货时可以去掉商品并只退那部分钱，所以付款要先授权、按实际金额扣（Nuvei 授权后部分完成，这一点要先确认，见下方未决事项）。
- **税**：沿用 `SalesTax` 规则，每个税率汇总后四舍五入一次，和柜台销售算法一致。

## 分期

1. **第 1 期：到店自取**
   - 店铺网址、商品目录（分类、搜索、规格选项、售罄）、购物车、线上付款、订单状态页。
   - Ourea / Iris 和 Cael 都能接单、出单。
   - 餐馆和零售都支持（零售含拣货单和缺货部分退款）。
2. **第 2 期：自家配送**（2026-11-17 完成：`docs/migrations/2026-11-17_arke_delivery.sql`。配送区按邮编前缀划分，不接地图服务；配送费按门店设的税率收税；
   线上配送单留在 `online.orders`，不复制到 `delivery_orders`；Ourea 多一列"配送中"，Iris 派送页列出"线上订单 · 已付款"；
   付款后通过 SMTP 发订单链接邮件，由 `_shared/arke-mail.ts` 后台发送，不阻塞付款确认）
   - 配送区和配送费、起送额、地址校验。
   - 线上订单进入 Iris 派送流程。订单已经线上付过款，司机只负责送到，不在门口收钱。
   - 顺带补上第 1 期漏的：下单后把订单状态链接发到顾客邮箱。
3. **第 3 期：第三方配送**
   - 接 Uber Direct 或 DoorDash Drive，按单付费：报价 → 叫车 → 回传骑手位置和状态。
4. **第 4 期：留住顾客**
   - 优惠券、会员、预约时段下单、再来一单、Google 好评提示。可以考虑加小海狸。
