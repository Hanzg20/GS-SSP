# Aegis Wash 1.1.6 / Aegis Timer 1.2.5 — 2026-10-21

Fix for 253 staying on the OPC page after a reboot (2026-10-21, 16:07 and 18:05 reboots), which
1.1.5 did not fix. Signed with the WizarPOS-certified release key.

## Cause
`BootFrontGuard` decided "covered" by counting our activities' start/stop callbacks. The splash
starts before the guard is installed, so the count was off: on 255 (a covered Wash, made with
`monkey -p com.wizarpos.opc`) it never acted at all, and on 253 it relaunched once, judged that
relaunch "still covered", and stopped. It also acted only at the moment of being covered, so OPC
coming to the front again after its start-up was never handled.

Android did not block anything: the HOME app's background start is allowed
(`BAL_ALLOW_ALLOWLISTED_COMPONENT` in 255's log).

## Change
- Every 3 s during the first 5 min after boot the guard asks the system whether the app is in
  the foreground (`ActivityManager.getMyMemoryState`) — no counting.
- Covered → relaunch, alternating the kiosk activity and the app's HOME entry, up to 6 times;
  same conditions as before (untouched screen, HOME holder).
- One `KIOSK_COVERED_AT_BOOT` report per boot with the timeline, sent once the kiosk has stayed
  in front for 30 s or the guard gives up, e.g.
  `back in front; 84s covered, #1 kiosk, 87s in front, 96s covered, #2 home, 99s in front, ...`

## Verified
255: rebooted, OPC brought over Wash three times (84 s, 96 s, 105 s after boot); each time Wash was
back within 3 s, both relaunch ways worked, report 526 arrived.

## After installing on 253 / 254
Check HOME (tech panel → System check) — installing Wash can take HOME from Timer. After the next
reboot read `KIOSK_COVERED_AT_BOOT` for the timeline.

## Kiosk in front, reported to Cael
- Each heartbeat carries `kiosk_in_front` (`KioskFront`, same system check as the guard;
  NULL while the screen is off and from attended apps) -> `devices.kiosk_in_front` /
  `kiosk_front_reported_at` (`docs/migrations/2026-10-21_kiosk_in_front.sql`, applied).
- `KioskFrontWatch` (started by `BootFrontGuard.install`, runs as long as the app does) checks
  every 30 s and sends a heartbeat right away when the kiosk has been covered for 2 min (a card
  sale's PAYWizard screen is shorter) and again when it is back.
- Cael shows "Screen covered" on the device (list badge, grid marker, panel / drawer notice).
- 255: OPC over Wash -> `f` reached the database ~4 min after covering (2 min wait + the
  heartbeat from the background took ~2 min); back in front -> `t` within a second.

## Wash: Scan Coupon / VIP Code on the payment page (customer request)
- Payment page offers "Pay with Card" and "Scan Coupon / VIP Code" (`payment_method_mode` 0);
  scan opens the camera and speaks the prompt every 7 s (at most 3 times, stops on a read, 25 s).
- VIP code pays the full price from the balance; FREE_WASH coupon starts the wash; a discount
  coupon goes to the card for the rest ("Coupon applied. Please tap your card to pay the rest.").
  A coupon is consumed only when it pays. No code / camera down / balance short / coupon for
  another wash -> back to the payment page with the reason shown and spoken.
- `settings.scan_pays_with`: CODE (default) | MOBILE_QR (old phone-QR page, not live).
- Database (`docs/migrations/2026-10-21_scan_code_payment.sql`, applied): modes 0 / 2 publish
  only when every wash terminal of the org runs 1.1.6+; Cael lists the ones to update.
- Tested on 255 (moved to the GoldSky Smart Wash test org for the test, then back): balance
  short, VIP pays $4, free coupon, 50% coupon -> card page (cancelled), no code -> timeout.

## SYNC_CONFIG after a store move
- The terminal asked for the config with the org id it had stored, so after a move in Cael it
  kept the old store's packages until restarted. `onSyncRequested` now refreshes the org first
  (`DeviceRepository.refreshOrgId`), Wash and Timer.
